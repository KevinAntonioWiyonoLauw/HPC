\begin{abstract}
\noindent
Laporan ini menyajikan hasil implementasi dan evaluasi akselerasi algoritma
\textit{Exact} $k$-Nearest Neighbors (k-NN) untuk tahap \textit{retrieval} pada
sistem \textit{Retrieval-Augmented Generation} (RAG), dikemas dalam aplikasi
demonstrasi \textbf{SIKA} (Sistem Informasi Kepatuhan Internal). Empat varian
\textit{engine} dikembangkan di atas satu kontrak antarmuka yang identik:
(1) \textit{baseline} CPU \textit{single-thread}; (2) OpenMP (paralelisasi blok
kueri + SIMD + \textit{cache tiling}); (3) CUDA berbasis GEMM (cuBLAS) dengan
penyempurnaan (\textit{refine}) jarak eksak; dan (4) MPI (\textit{sharding} +
\textit{Gather}). Seluruh kriteria kelulusan K1--K7 yang ditetapkan
\textit{sebelum} pengukuran berhasil dipenuhi, termasuk \textit{speedup} OpenMP
$17{,}23\times$, \textit{speedup} CUDA $244{,}55\times$, latensi p95 per-kueri
CUDA $2{,}59$~ms, dan \textit{recall} 100\% yang identik dengan \textit{baseline}.
\end{abstract}

\section{Pendahuluan}
% =====================================================================
\subsection{Latar Belakang}
Sistem RAG menjawab pertanyaan dengan terlebih dahulu mengambil (\textit{retrieve})
potongan dokumen paling relevan dari basis pengetahuan, lalu menyusun jawaban
berbasis konteks tersebut. Pada domain kepatuhan internal, \textit{retrieval}
tidak boleh melewatkan pasal pengecualian atau ambang batas nominal; karena itu
dipilih \textit{Exact} $k$-NN (bukan \textit{Approximate Nearest Neighbor}) agar
\textit{recall} tetap 100\%.

Namun, komputasi \textit{exact} $k$-NN sekuensial berkompleksitas
$\mathcal{O}(Q \times N \times D)$ dan sangat lambat pada skala ratusan ribu
vektor. Dua \textit{bottleneck} utama: (1) \emph{memory-bound} --- matriks basis
($N \times D \times 4$ byte) jauh melampaui LLC 12~MB sehingga terjadi
\emph{cache thrashing}; dan (2) \emph{compute-bound} --- aritmatika belum
memanfaatkan paralelisasi data (SIMD) maupun GPU secara optimal.

\subsection{Tujuan}
Mengimplementasikan dan mengevaluasi akselerasi \textit{exact} k-NN berlapis
(OpenMP, CUDA, MPI), memetakan \textit{bottleneck} secara kuantitatif, serta
mengintegrasikannya ke dalam aplikasi SIKA yang dapat didemonstrasikan langsung
dengan \textit{engine} yang dapat ditukar saat berjalan.

\subsection{Desain Engine}
Seluruh varian mengekspos satu tanda tangan fungsi identik
(\texttt{KnnSearchFn}) sehingga perbandingan mencerminkan perbedaan
implementasi, bukan protokol pemanggilan.

\begin{table}[H]
\centering
\caption{Varian \textit{engine} dan teknik optimasi.}
\label{tab:engine}
\begin{tabularx}{\linewidth}{@{}l X@{}}
\toprule
\textbf{Engine} & \textbf{Teknik}\\
\midrule
\texttt{baseline} & CPU \textit{single-thread}, $d^2=\sum (q_i-p_i)^2$ langsung\\
\texttt{openmp} & Paralelisasi blok kueri (\texttt{schedule(dynamic)}) + \texttt{\#pragma omp simd} + \textit{cache tiling} (blok $Q=64$)\\
\texttt{cuda} & \texttt{cublasSgemm} menghitung $\mathbf{Q}\cdot\mathbf{B}^{\top}$ (\textit{shortlist}) + \textbf{refine eksak} $\sum(q_i-p_i)^2$ pada kandidat + reduksi top-$k$ di \textit{shared memory}\\
\texttt{mpi} & \textit{Sharding} kontigu (tiap proses memuat hanya $\lceil N/P \rceil$ baris) + \texttt{MPI\_Gather} top-$k$ lokal $\rightarrow$ \textit{merge} eksak di rank 0\\
\bottomrule
\end{tabularx}
\end{table}

\paragraph{Catatan presisi CUDA.} Ekspansi aljabar
$d^2=\lVert q\rVert^2+\lVert p\rVert^2-2(q\cdot p)$ memungkinkan operasi GEMM
yang sangat cepat, tetapi rentan \emph{catastrophic cancellation} pada
\textit{float32} (nilai $\lVert q\rVert^2+\lVert p\rVert^2$ besar, sedangkan
$d^2$ kecil). Untuk menjamin kriteria K5 (hasil identik \textit{baseline}),
kernel GEMM hanya dipakai sebagai \textit{shortlist} cepat; kandidat teratas
kemudian dihitung ulang dengan rumus eksak $\sum(q_i-p_i)^2$. Pendekatan ini
mempertahankan kecepatan GEMM sekaligus akurasi 100\%.

\subsection{Dataset}
Data sintetis berdistribusi seragam dengan \textit{seed} tetap (reproduksibel),
\textit{float32}, $D=384$; $N \in \{50.000, 100.000, 250.000, 500.000\}$.
Korpus demonstrasi memakai SOP internal terkurasi (jawaban pasti) diperkaya
potongan referensi hingga skala realistis.

\section{Analisis \textit{Bottleneck}}
% =====================================================================
\begin{itemize}
  \item \textbf{Memory-bound (CPU).} Matriks basis $N=100.000$, $D=384$
  berukuran $\approx 153{,}6$~MB, melampaui LLC 12~MB $\approx 12{,}8\times$.
  \textit{Baseline} membaca ulang seluruh matriks untuk tiap kueri. \textit{Cache
  tiling} pada OpenMP (blok kueri) meningkatkan \textit{reuse} baris basis
  sehingga OpenMP 1 thread pun sudah $5{,}77\times$ lebih cepat dari
  \textit{baseline} meski hanya 1 thread.
  \item \textbf{Compute-bound (GPU).} GPU GTX 1650 (4~GB) unggul pada
  \textit{throughput} masif. Operasi inti dipetakan ke GEMM cuBLAS yang sangat
  teroptimasi, menghasilkan \textit{speedup} batch hingga $244{,}55\times$.
  \item \textbf{Komunikasi (MPI).} Pada satu mesin 4 core, proses MPI bersaing
  memperebutkan core dan \textit{bandwidth} memori; karena itu MPI diposisikan
  sebagai jalur \emph{skalabilitas kapasitas} (menurunkan jejak memori per
  proses), bukan percepatan latensi.
\end{itemize}

\section{Sistem Terdemostrasi (SIKA)}
% =====================================================================
\subsection{Arsitektur}
SIKA dibagi menjadi empat lapisan pada satu mesin:
\begin{enumerate}
  \item \textbf{Antarmuka (Web UI)} --- Vite + React + TypeScript; menampilkan
  jawaban, kutipan pasal, dan panel telemetri (p50/p95, QPS, \textit{engine} aktif).
  \item \textbf{Layanan (API)} --- FastAPI dengan endpoint \texttt{/ask},
  \texttt{/search}, \texttt{/engine}, \texttt{/config}, \texttt{/models},
  \texttt{/bench}.
  \item \textbf{Retrieval HPC} --- \textit{engine} C++ (\texttt{baseline},
  \texttt{openmp}, \texttt{cuda}, \texttt{mpi}) yang diekspos ke Python via
  \texttt{pybind11}, dapat ditukar saat berjalan tanpa \textit{restart}.
  \item \textbf{Data} --- matriks vektor \textit{float32} $N\times D$ + metadata
  pasal.
\end{enumerate}

\subsection{Alur Permintaan \texttt{POST /ask}}
Pertanyaan $\rightarrow$ embedding (all-MiniLM-L6-v2, $D=384$) $\rightarrow$
$k$-NN (\textit{engine} aktif) $\rightarrow$ pemetaan metadata pasal $\rightarrow$
prompt ke LLM lokal/eksternal $\rightarrow$ jawaban + kutipan + rincian latensi.
Hanya tahap \textit{retrieval} yang dioptimasi; tahap lain identik antar
konfigurasi.

\subsection{Integrasi LLM}
LLM memakai protokol \emph{OpenAI-compatible} yang dapat dikonfigurasi saat
berjalan (Base URL, API Key, model via ``Fetch Models''). Bila penyedia gagal
atau kena \textit{rate-limit} (HTTP 429), sistem otomatis \emph{fallback} ke
jawaban \emph{extractive} dari pasal hasil \textit{retrieval}, sehingga demo tetap
berjalan luring.

\subsection{Skenario Demonstrasi}
D1 menjalankan sistem; D2 tanya normal; D3 beban 100 kueri serentak (QPS,
p50/p95); D4 tukar \textit{engine} live (\texttt{baseline}$\rightarrow$\texttt{openmp}$\rightarrow$\texttt{cuda});
D5 verifikasi \textit{recall} 100\%; D6 jawab $<1$~detik; D7 jalur mundur CPU
tanpa GPU.

\section{Kesimpulan}
% =====================================================================
Akselerasi \textit{exact} k-NN berlapis berhasil memenuhi seluruh kriteria
kelulusan K1--K7 dengan \textit{recall} tetap 100\%: OpenMP $17{,}23\times$,
CUDA $244{,}55\times$ (batch) dengan p95 per-kueri $2{,}59$~ms, efisiensi
paralel $74{,}6\%$, dan reduksi jejak memori MPI $3{,}70\times$. Optimasi
tersebut terintegrasi dalam aplikasi SIKA yang dapat dioperasikan dan
didemonstrasikan langsung, dengan \textit{engine} yang dapat ditukar saat
berjalan.

\subsection*{Saran Pengembangan}
Implementasi hibrida MPI+CUDA (multi-GPU per simpul), eksplorasi presisi rendah
(\textit{float16/bfloat16}, \textit{tensor core}), pembandingan terhadap pustaka
industri (mis.\ FAISS-GPU), serta peningkatan korpus regulasi publik nyata untuk
memperkuat validasi domain.

\section{Cara Reproduksi}
% =====================================================================
\begin{lstlisting}[language=bash]
# 1) Build engine
cd engine && make bench bench_openmp bench_cuda mpi && cd ..
# 2) Binding Python (baseline+openmp+cuda)
bash scripts/build_binding.sh
# 3) Korpus demo (SOP terkurasi + filler)
bash scripts/build_corpus.py --filler 20000
# 4) Evaluasi K1..K7 -> results/report/kpi_summary.json + REPORT.md
python scripts/evaluate_all.py --n 100000 --d 384 --q 1000 --k 10 --reps 3 --mpi-n 500000
python scripts/make_report.py
# 5) Jalankan layanan + web
bash scripts/run_service.sh          # http://0.0.0.0:8000
cd web && npm install && npm run dev # http://localhost:5173
\end{lstlisting}

\noindent\textbf{Catatan lingkungan.} Untuk \textit{engine} CUDA di WSL2,
gunakan \texttt{LD\_LIBRARY\_PATH=/usr/lib/wsl/lib} agar \texttt{libcuda.so}
WSL terpilih. Penyedia LLM di Windows diakses dari WSL melalui IP host (bukan
\texttt{127.0.0.1}); \texttt{run\_service.sh} menanganinya otomatis.
